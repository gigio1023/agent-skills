# Surface Patterns

Pick the surface first. The same colors and components can feel excellent or wrong depending on what the screen is for.

## Product App

Purpose: repeated use, fast scanning, low friction.

Design for:
- Predictable navigation, clear entry and exit points, one primary action per region.
- Quiet density: enough information to work, not enough decoration to slow the user.
- Strong states: loading, empty, error, success, disabled, hover, active, focus.
- UI controls that match user intent: toggles for binary state, segmented controls for modes, sliders or steppers for numeric values, menus for option sets, icon buttons for familiar actions.

Avoid:
- Marketing hero layouts inside an app.
- Cards nested inside cards.
- Decorative section wrappers that reduce usable space.

## Dashboard Or Analytics

Purpose: turn data into decisions.

Design for:
- A clear reading order: current state, change, cause, action.
- Numbers with context: unit, timeframe, comparison, and uncertainty where relevant.
- Tables and charts that can handle long labels, missing data, and large values.
- Tabular numerals for comparable values.
- One accent system for selected/active/high-priority information, with status colors used sparingly.

Avoid:
- Chart walls without interpretation.
- Color-only meaning.
- KPI cards that all share identical weight, size, and rhythm.
- Decorative charts that do not answer a question.

## Static HTML Report

Purpose: readable, durable, shareable analysis.

Design for:
- Document hierarchy: title, scope/date, executive summary, evidence, recommendation.
- Tables that are legible on desktop and tolerable on mobile.
- Section bands, captions, footnotes, callouts, and diagrams that clarify the argument.
- Print/export friendliness when likely: stable widths, no hidden critical content, sensible page breaks.
- Visual restraint. Let charts, tables, annotations, and typographic hierarchy carry the design.

Avoid:
- Landing-page hero theatrics.
- Huge decorative typography that makes the report harder to read.
- Motion unless the report is intentionally interactive.

## Landing Or Brand Page

Purpose: explain an offer and create desire.

Design for:
- First viewport as a thesis: brand/product/place/person is immediately visible.
- One dominant visual anchor: real product image, generated image, video, 3D scene, interactive demo, or strong typographic concept.
- Sections with different jobs: promise, proof, mechanism, details, action.
- Copy that says what the user gets and why it matters.

Avoid:
- Split text/card hero when a full-bleed subject image or interactive anchor would say more.
- Generic stat strips unless the numbers are truly the proof.
- Decorative texture as the only visual substance.

## Portfolio Or Career Page

Purpose: show judgment, evidence, and fit.

Design for:
- Case evidence over slogans.
- Project cards that reveal problem, role, decision, result.
- A visual system that matches the person's domain, not a generic personal-brand template.
- Download/print paths if the artifact doubles as application material.

Avoid:
- Overly clever navigation.
- Hiding evidence behind animation.
- Treating every project as equally important.

## Game Or Interactive Demo

Purpose: play, feel, experiment.

Design for:
- Immediate affordance: the user knows what can be touched or controlled.
- A full-bleed or clearly primary play surface.
- Motion, sound, and feedback that support the game loop.
- Stable canvas dimensions and mobile controls if relevant.
- Libraries for established rules, physics, 3D, parsing, or AI behavior unless the user asks for from-scratch.

Avoid:
- UI chrome competing with the play area.
- Blank or off-frame canvas.
- Motion that ignores `prefers-reduced-motion` for nonessential effects.

## Docs, Guides, Or Knowledge Tools

Purpose: comprehension and retrieval.

Design for:
- Clear information scent: headings, examples, callouts, code blocks, search, anchors.
- Dense but readable layout.
- Stable links and copyable commands.
- Examples close to the explanation they support.

Avoid:
- Decorative cards around every paragraph.
- Fancy typography that weakens scanning.
