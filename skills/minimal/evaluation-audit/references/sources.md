# Sources and Scope

Reviewed October 3, 2026 while authoring the verdict, the health checklist, the scoring-change gate, and release mode.

- [Anthropic skills, `claude-api` eval references](https://github.com/anthropics/skills) at `8a1541c` (2026-09-29), `skills/claude-api/shared/evals/eval-audit.md`: inspected the full health checklist (task design, harness design, metrics hygiene, grader design, detectability) and its reporting section. Adopted the end-to-end run before auditing, oracle and null passes, error records kept apart from scored rows, the served-model check, configuration parity with production, the noise floor against the smallest worthwhile change, severity order, and observation framing. Not adopted: offering to fix findings during the audit (this skill returns fixes to the owner), the per-case auditor prompt, and its file names. Its reader ships applications built on one provider's models; its numbers are defaults here.
- [UK AISI Inspect Evals](https://github.com/UKGovernmentBEIS/inspect_evals) at `0dacad3` (2026-10-02), `.claude/skills/eval-validity-review`, `verify-scoring-change`, and `check-trajectories-workflow`: inspected the three skill files in full. Adopted the claims inventory before mechanics, name validity, the test that each sample can be both passed and failed, verifiable compliance, the scale from direct measurement to weak proxy, the scoring-change questions with the receipts rule, exclusion values and parser-tolerance probes, and trajectory flags with the direction each one invalidates. Not adopted: its commands, directory layout, version-numbering rules, and report templates. It reviews benchmark implementations in one repository; the questions transfer, the procedures do not.
- [Hamel Husain and Shreya Shankar, evals-skills](https://github.com/ai-evals-course/evals-skills) at `80d5f7b` (2026-09-24), `eval-audit` and `validate-evaluator` skills: inspected the six diagnostic areas, the report format, and the validation protocol. Adopted class-conditional agreement rates over raw accuracy with their target and floor as defaults, few-shot examples kept out of the measurement split, labeler expertise and full-trace review, and re-validation after pipeline changes. Not adopted: binary evaluators as a rule, trace counts as gates, and the error-analysis routing, which is design work for product applications.
- [promptfoo red-team run skill](https://github.com/promptfoo/promptfoo) at `8e6b3fa` (2026-10-02), `plugins/promptfoo/skills/promptfoo-redteam-run`: inspected the full skill. Adopted the success rate over validly graded results, zero graded results as inconclusive, and persisted state as the evidence for tool-using targets. Not adopted: commands and CI thresholds.
- [Microsoft PyRIT](https://github.com/microsoft/PyRIT) at `38d7e11` (2026-10-02), `doc/blog/2026_04_14_scoring_scorers.md` and `doc/blog/2026_07_09_scenarios.md`: scorer metrics bound to an identity over prompt, rubric, model, and temperature, and a baseline pass without the technique. First taken from a secondary summary; both files were reopened at this revision on October 7, 2026 and support these two points.
- [NVIDIA garak](https://github.com/NVIDIA/garak) at `8d1259e` (2026-09-16), `docs/source/analyze/tbsa.rst`: a summary score is comparable only under the same tool version and configuration and should not replace the run report. First taken from a secondary summary; the file was reopened at this revision on October 7, 2026 and states both points, including a checksum for comparability.

The verdict table, the authority rules, release mode, the synthetic example, and the split between design and audit are independently authored. The sources do not establish that these instructions improve agent behavior, and package validation does not establish that any audited eval is sound.
