# 한국어 작성

한국어 문서를 쓰거나 명료성을 고칠 때 읽는다. 짧은 일반 답변과 진행 보고에는 아래 원칙을 적용하되 추가 참조를 모두 읽을 필요는 없다. 이 파일은 한국어의 의미와 표현을 맡고 구두점, 용어 표기, 문체 같은 저자 취향은 [writing-profile.md](writing-profile.md)가 맡는다.

## 명료성 기준

핵심어만 남겨 조사, 어미, 서술어가 사라지면 관계를 되살린다. 한 문장에 서로 다른 대상과 조건이 겹쳐 읽기 어려우면 나눈다. 인과나 대조가 자연스럽게 이어지는 문장은 유지한다. 연결어미 개수와 문장 길이만으로 교정하지 않는다.

독자가 되살리지 못하는 가장 작은 단위에서 명제(누가 무엇을 하고 무엇이 바뀌는지), 경계(조건, 시점, 범위, 요구 수준, 불확실성), 연결(인과, 대조, 순서, 목적), 지시(대명사, 생략 주어, 약어가 가리키는 것), 격식 가운데 무엇이 빠졌는지 본다. 문맥이 관계를 이미 정하면 생략은 정상 한국어다. 생략 주어마다 확인 질문을 만들지 않고 요청된 뜻을 바꾸는 모호함만 묻는다.

- 성분 복원: 빠진 행위자, 대상, 조건은 문맥이 정해 주고 빠지면 모호할 때만 채운다. 지시 대상이 둘 이상일 수 있으면 정확한 명사를 반복한다.
- 설명 산문의 완결: 독립된 진술은 서술어와 종결어미로 끝낸다. 제목, label, 표 셀, 병렬 목록 항목, 주석, 의도한 단편, 요약 블록 항목은 단편으로 둔다. 병렬 사실은 개괄식이어도 되지만 원인, 조건, mechanism은 tracker 종료 메모에서도 문장으로 쓴다.
- 조사와 어미: 문법 역할, 시제, 허용, 가능성, 높임, 절 사이 관계를 드러내는 만큼 되살린다. 문장을 채우려고 보조 용언이나 부사를 더하지 않는다.
- 명사열 풀기: 행위 주체나 수식 관계를 가리는 명사 나열은 조사를 복원하거나 절로 푼다. 현업에 정착한 복합 명사와 기술 명사구는 둔다.
- 평범하고 정확한 단어: 낯선 비유, 드문 사전 어휘, 장식 외래어는 평범한 단어로 되돌린다. 한자어라서 더 정확하지는 않다. 분야의 관용 비유와 저자가 의도한 이미지는 둔다.
- 한 대상 유지: 기술 문단은 한 대상을 계속 보여 주며 새 용어를 서술어로 그 대상에 잇는다. 인과와 대조 표현은 실제 관계를 나를 때 둔다.
- 격식: 한 문서는 한 격식이고 기존 존댓말은 유지한다. `-다` 어미를 일정하게 써도 된다.

이름, 수치, 원인, 예, 의도를 지어내 구체화하지 않는다. 사용자의 오타, 불완전한 축약, 일시적인 속어를 모방하지 않는다. 남의 글은 요청된 범위 안에서 고치고 의도한 단편, 방언, 비모국어 화자의 목소리를 둔다. 관계가 되살아나면 끝내고 분명한 문장을 더 풍성하게 다시 쓰지 않는다.

### 합성 예시

**근거가 있는 mechanism 확장.** "업로드 완료 후 검색 미반영 가능. 저장과 인덱스 분리, worker 후속 처리."에 어미만 붙이면 "worker가 나중에 처리한다"처럼 어느 작업이 어느 저장소에 닿는지가 비어 있다.

**함께 주어진 근거**: service는 파일 저장과 durable enqueue 후 업로드 응답을 보낸다. ID lookup은 저장된 파일을 읽고 keyword search는 worker가 갱신하는 index를 읽는다. 이 근거가 없으면 원문의 “저장과 index 갱신이 분리된다”까지만 설명한다.

> 업로드 응답은 파일이 저장되었고 indexing job이 durable queue에 들어갔다는 뜻이다. ID lookup은 저장된 파일을 바로 읽지만 keyword search는 worker가 나중에 갱신하는 별도 index를 조회한다. 그래서 업로드가 성공한 직후에는 ID로 파일을 조회할 수 있어도 keyword search 결과에는 아직 나타나지 않을 수 있다.

세 문장이 한 파일을 지시 대상으로 유지하며 함께 주어진 계약을 설명한다. 전문가용 상태 표라면 짧은 label로 충분하다.

**용어와 계산.** "Arithmetic mean, 동일 가중치, 합 나누기 관측 수. 결과 8."을 용어를 처음 배우는 독자에게 쓴다. 이 합성 예시에는 관측값 6과 10도 함께 주어졌다. 원문에 결과만 있다면 관측값을 역으로 지어내지 않는다.

> Arithmetic mean(산술평균)은 관측값을 더한 뒤 관측값의 개수로 나눈 값이다. 관측값이 6과 10이면 `(6 + 10) / 2 = 8`이다. 이 계산에서 두 관측값의 가중치는 각각 1/2이다.

풀이는 첫 등장에만 붙인다.

**범위가 드러나는 부정.** "실패 이후 진행하지 않는다. 필요하면 다시 처리한다."에는 조건, 주체, 다음 행위자가 빠졌다.

> 실패한 뒤에는 계속 진행하지 않는다. 필요한 경우 다시 처리한다.

원문만으로는 실패 종류, 재처리 주체, 자동 재시도 여부를 정할 수 없다. 실제 동작 설명에 이 구분이 필요하면 근거를 확인한다. 단순한 문장 교정으로 client나 timeout을 추가하지 않는다.

**조사 대상 복원.** "재시도 증가에 따른 queue 영향 확인 필요"는 "재시도가 늘어날 때 queue에 어떤 영향이 있는지 확인해야 한다"가 된다. 지표를 고르거나 영향이 관찰됐다고 쓰지 않는다.

**가능성의 경계.** "이 설정에서는 연결이 끊길 수 있다"를 "끊긴다"로 바꾸면 주장이 강해진다.

## 섹션 제목

섹션 제목은 논문의 소제목처럼 주제와 논리적 역할을 드러내는 전문적인 명사구로 쓴다. `~했네요`, `~입니다`, `~해요`, `~합니다` 같은 종결어미가 붙은 문장이나 `~살펴보겠습니다`, `~알아볼까요` 같은 읽기 안내를 제목으로 쓰지 않는다. 설명과 주장은 본문에서 문장으로 전개한다. 이 기준은 제목에 적용하며 본문의 존댓말이나 자연스러운 복문을 제한하지 않는다.

아래는 제목 표현만 비교하는 합성 예시다. 실제 문서에서는 본문이 다루는 주제와 근거에 맞춰 제목을 고른다.

| 문장형 제목 | 전문적인 섹션 제목 |
|---|---|
| 성능이 개선됐네요 | 성능 개선 결과 |
| 이 방법의 한계입니다 | 방법의 한계 |
| 실패 원인을 살펴봐요 | 실패 원인 분석 |
| 두 모델을 비교해 볼게요 | 모델별 성능 비교 |
| 요청이 실패하면 다시 실행합니다 | 요청 실패 시 재시도 정책 |

명사구라도 `관련 내용`, `알아둘 사항`처럼 절의 내용을 식별하지 못하면 구체화한다. `~함`, `~임`만 붙여 문장을 축약하는 것도 충분하지 않다. 필요한 전문용어와 조건은 남긴다. `장기 실행 agent의 중단 이후 상태 복구`처럼 수식어가 필요한 제목에 글자 수 제한을 두지 않는다. 사용자가 그대로 유지하도록 지정했거나 필수 template이 정한 제목은 유지한다.

## 용어와 영어 경계

컴퓨터 과학, 보안, 머신러닝과 AI 연구처럼 작업 어휘가 영어로 정착한 분야의 용어는 English term으로 쓴다(endpoint, runtime, judge, ablation). 필요한 첫 등장에 한국어 풀이를 붙이고 이후에는 같은 term을 유지한다. 영어 표기 자체는 결함이 아니다. 제품, API, protocol 이름은 똑같이 정확한 한국어 형태가 없으면 원어로 둔다. 일반 동사와 명사는 한국어로 쓴다. "acknowledge한다"는 "확인 응답을 보낸다", "enqueue가 끝났다"는 "queue에 들어갔다"로 쓴다. 영어 용어를 쓰겠다고 알리는 방침 문단은 쓰지 않는다.

영어 표현을 평범한 한국어로 바꿀 때도 분야의 뜻을 먼저 확인한다. `robust regression`은 방법 이름이므로 과장 형용사로 보고 지우지 않는다. 회사와 프로젝트 고유 용어는 기록된 terminology를 따른다.

## 부정형 정의

무엇인지 먼저 쓴다. "X가 아니라 Y"는 독자가 X로 가정할 근거가 있을 때만 쓴다. 판정은 부정절을 지워 보는 것이다. 주장이 그대로 남으면 수사적 대구이므로 지우고 무엇을 바로잡는지가 사라지면 정정 문장이므로 둔다. 반복돼도 각각 실제 오해를 바로잡으면 둔다. 기술 문서에서는 부정절이 authority, 실패 조건, 미지원 범위를 정의할 수 있다.

`~않는다`는 결함이 아니다. 실제 부정, 금지, 미지원 범위를 나르면 두고 긍정으로 뒤집거나 조건을 지우지 않는다. "이 문서는 모든 사례를 설명하지 않는다" 같은 분명한 문장이 필요한지는 별개의 편집 선택이다.

## 선택적 표현 점검

반복 표현이 실제 설명을 가리거나 같은 내용을 되풀이할 때 그 부분을 고친다. “이를 통해”, “할 수 있다”, “결국” 같은 형태만으로 삭제를 결정하지 않는다. 대명사의 지시 대상, 가능성, 인과관계가 분명하면 유지한다. 특정 패턴의 측정 근거가 필요한 경우에만 [한국어 반복 표현의 근거](korean-pattern-evidence.md)를 읽는다.

## 구두점
