# 한국어 작성

한국어 문서를 쓰거나 고칠 때 읽고 한국어 일반 답변, 진행 보고, 최종 답변에도 적용한다. 이 파일은 한국어의 의미와 표현을 맡고 구두점, 용어 표기, 문체 같은 저자 취향은 [writing-profile.md](writing-profile.md)가 맡는다.

## 명료성 기준

흔한 실패는 압축이다. 핵심어는 남고 그 관계를 보이는 조사, 어미, 서술어가 빠진다. 고칠 대상은 빠진 관계이며 문장 길이는 기준이 되지 않는다.

독자가 되살리지 못하는 가장 작은 단위에서 명제(누가 무엇을 하고 무엇이 바뀌는지), 경계(조건, 시점, 범위, 요구 수준, 불확실성), 연결(인과, 대조, 순서, 목적), 지시(대명사, 생략 주어, 약어가 가리키는 것), 격식 가운데 무엇이 빠졌는지 본다. 문맥이 관계를 이미 정하면 생략은 정상 한국어다. 생략 주어마다 확인 질문을 만들지 않고 요청된 뜻을 바꾸는 모호함만 묻는다.

- 성분 복원: 빠진 행위자, 대상, 조건은 문맥이 정해 주고 빠지면 모호할 때만 채운다. 지시 대상이 둘 이상일 수 있으면 정확한 명사를 반복한다.
- 설명 산문의 완결: 독립된 진술은 서술어와 종결어미로 끝낸다. 제목, label, 표 셀, 병렬 목록 항목, 주석, 의도한 단편, 요약 블록 항목은 단편으로 둔다. 병렬 사실은 개괄식이어도 되지만 원인, 조건, mechanism은 tracker 종료 메모에서도 문장으로 쓴다.
- 조사와 어미: 문법 역할, 시제, 허용, 가능성, 높임, 절 사이 관계를 드러내는 만큼 되살린다. 문장을 채우려고 보조 용언이나 부사를 더하지 않는다.
- 명사열 풀기: 행위 주체나 수식 관계를 가리는 명사 나열은 조사를 복원하거나 절로 푼다. 번역투 A-13도 이 규칙으로 다룬다. 현업에 정착한 복합 명사와 기술 명사구는 둔다.
- 평범하고 정확한 단어: 낯선 비유, 드문 사전 어휘, 장식 외래어는 평범한 단어로 되돌린다. 한자어라서 더 정확하지는 않다. 분야의 관용 비유와 저자가 의도한 이미지는 둔다.
- 한 대상 유지: 기술 문단은 한 대상을 계속 보여 주며 새 용어를 서술어로 그 대상에 잇는다. 인과와 대조 표현은 실제 관계를 나를 때 둔다.
- 격식: 한 문서는 한 격식이고 기존 존댓말은 유지한다. `-다` 어미를 일정하게 써도 된다.

이름, 수치, 원인, 예, 의도를 지어내 구체화하지 않는다. 사용자의 오타, 불완전한 축약, 일시적인 속어를 모방하지 않는다. 남의 글은 허용된 범위만 고치고 의도한 단편, 방언, 비모국어 화자의 목소리를 둔다. 관계가 되살아나면 끝내고 분명한 문장을 더 풍성하게 다시 쓰지 않는다.

### 합성 예시

**명사열에서 mechanism으로.** "업로드 완료 후 검색 미반영 가능. 저장과 인덱스 분리, worker 후속 처리."에 어미만 붙이면 "worker가 나중에 처리한다"처럼 어느 작업이 어느 저장소에 닿는지가 비어 있다.

> 업로드 응답은 파일이 저장되었고 indexing job이 durable queue에 들어갔다는 뜻이다. ID lookup은 저장된 파일을 바로 읽지만 keyword search는 worker가 나중에 갱신하는 별도 index를 조회한다. 그래서 업로드가 성공한 직후에는 ID로 파일을 조회할 수 있어도 keyword search 결과에는 아직 나타나지 않을 수 있다.

세 문장이 한 파일을 지시 대상으로 유지하며 없는 지연 시간이나 원인은 넣지 않았다. 전문가용 상태 표라면 짧은 label로 충분하다.

**용어와 계산.** "Arithmetic mean, 동일 가중치, 합 나누기 관측 수. 결과 8."을 용어를 처음 배우는 독자에게 쓴다.

> Arithmetic mean(산술평균)은 관측값을 더한 뒤 관측값의 개수로 나눈 값이다. 관측값이 6과 10이면 `(6 + 10) / 2 = 8`이다. 이 계산에서 두 관측값의 가중치는 각각 1/2이다.

풀이는 첫 등장에만 붙인다.

**범위가 드러나는 부정.** "실패 이후 진행하지 않는다. 필요하면 다시 처리한다."에는 조건, 주체, 다음 행위자가 빠졌다.

> 이 client는 timeout이 발생하면 자동으로 재시도하지 않는다. 다시 시도하려면 호출자가 새 요청을 보내야 한다.

부정 어미가 실제 동작을 나르므로 "호출자가 요청을 보낸다"로 줄이면 조건과 자동 재시도의 부재가 사라진다.

**조사 대상 복원.** "재시도 증가에 따른 queue 영향 확인 필요"는 "재시도가 늘어날 때 queue에 어떤 영향이 있는지 확인해야 한다"가 된다. 지표를 고르거나 영향이 관찰됐다고 쓰지 않는다.

**가능성의 경계.** "이 설정에서는 연결이 끊길 수 있다"를 "끊긴다"로 바꾸면 주장이 강해진다(A-10).

## 용어와 영어 경계

컴퓨터 과학, 보안, 머신러닝과 AI 연구처럼 작업 어휘가 영어로 정착한 분야의 용어는 English term으로 쓴다(endpoint, runtime, judge, ablation). 필요한 첫 등장에 한국어 풀이를 붙이고 이후에는 같은 term을 유지한다. 영어 표기 자체는 결함이 아니다. 제품, API, protocol 이름은 똑같이 정확한 한국어 형태가 없으면 원어로 둔다. 일반 동사와 명사는 한국어로 쓴다. "acknowledge한다"는 "확인 응답을 보낸다", "enqueue가 끝났다"는 "queue에 들어갔다"로 쓴다. 영어 용어를 쓰겠다고 알리는 방침 문단은 쓰지 않는다.

B-1과 B-2는 적용 대상이 다르다. B-1은 설명이 필요한 분야 용어의 첫 풀이와 기준 용어 유지다. B-2는 일반 문장 속 영어이며 leverage, seamless, robust처럼 직역 가능한 말은 한국어를 검토하고 pipeline처럼 더 익숙한 업계 표준어는 둔다. 한 문서 안에서 같은 말의 표기는 하나로 맞춘다. 둘 다 편집 기준이고 저자 판별 신호가 아니다. 회사와 프로젝트 고유 용어는 use-terminology의 기준을 따른다.

## 부정형 정의

무엇인지 먼저 쓴다. "X가 아니라 Y"는 독자가 X로 가정할 근거가 있을 때만 쓴다. 판정은 부정절을 지워 보는 것이다. 주장이 그대로 남으면 수사적 대구이므로 지우고 무엇을 바로잡는지가 사라지면 정정 문장이므로 둔다. 반복돼도 각각 실제 오해를 바로잡으면 둔다. C-8의 측정 근거는 논설과 블로그 산문이며 기술 문서가 아니다. 기술 문서에서 정의를 다시 세우는 같은 표면형은 정보를 나를 수 있다.

`~않는다`는 결함이 아니다. 실제 부정, 금지, 미지원 범위를 나르면 두고 긍정으로 뒤집거나 조건을 지우지 않는다. "이 문서는 모든 사례를 설명하지 않는다" 같은 분명한 문장이 필요한지는 별개의 편집 선택이다.

## 근거 있는 표지

상류는 `epoko77-ai/im-not-ai` humanize-korean v2.3.0이다. `[self]` 수치는 LLM 문서 60건과 2022년 이전 사람 출판 산문 60건의 비교이며 주제가 짝지어지지 않았고 코퍼스가 비공개다. 검토 순서의 단서로만 쓴다.

|---|---|---|---|---|
| C-11 연결어미 뒤 쉼표 | 에세이 비율 사람 4.10%, LLM 19.83% | `[AI]` KatFish | 집단 비율이며 한 span의 기준이 아님. AUC 94.88%는 구두점 feature 전체 수치 | 불필요한 쉼표는 지우고 인용과 뜻을 나르는 쉼표는 둔다 |
| C-8 부정 대구 | 논설 대비 9.2배, 블로그 대비 18배 | `[self]` | 60 대 60, 주제 비대응, 코퍼스 비공개, 논설과 블로그 | 부정형 정의 절의 판정 |

번역투 목록은 `[KO]` 근거의 문맥 단서이며 보편 금지나 저자 판별 근거가 되지 않는다. 관계가 더 분명해질 때만 바꾼다. 문헌은 국립국어원의 2012년 글 두 편([김정우](https://www.korean.go.kr/nkview/nklife/2012_1/22_0104.pdf), [김순영](https://www.korean.go.kr/nkview/nklife/2012_1/22_0105.pdf))이다.

## 운용 규칙

- 등급: `[AI]`는 외부 연구의 집단 차이이며 한 span이나 한 문서의 증명이 아니다. `[self]`는 코퍼스와 재현 script가 없는 상류 자체 연구다. `[KO]`는 번역투 문헌이며 보편 금지나 AI 저자 판정이 아니다. `[obs]`는 관찰 전용이며 수정 지시가 아니다.
- 순회 금지: 한국어라는 이유로 ID 목록 전체를 기계적으로 훑지 않는다. 공통 진단 뒤에 남은 반복 형태가 있을 때 해당 항목만 본다.
- 순서는 점수가 아니다: S1은 먼저 보되 한 번의 출현으로 저자를 추정하지 않는다. S2는 세 번 이상이거나 몰릴 때 고친다. 패턴 개수나 변경 비율로 문서를 채점하지 않는다.
- 유지 보수: 분기마다 상류 `references/ai-tell-taxonomy.md`와 `empirical-validation.md`를 대조해 ID 단위 변경만 옮긴다. 마지막 대조는 2026-07-31(`main` `53e24e8`, v2.3.0 `82137e8`).

## 구두점

구두점 house 규칙은 [writing-profile.md](writing-profile.md)를 따르되 dash 자리를 연결어미 뒤 쉼표로 바꾸지 않고(C-11) 잇거나 마침표로 끊으며 인용, 코드, 공식 명칭은 원래 기호를 유지한다.
