# PR Body Anti-Patterns

본문 검토 시 이 표와 매칭되는 패턴이 있으면 수정합니다.

| Bad | Good |
|-----|------|
| 반말/명사 종결 ("수정", "추가했음") | 존댓말 ("수정했습니다", "추가합니다") |
| 반복과 파일 나열로 불필요하게 긴 본문 | 일반 PR은 약 20줄 이내, 작은 PR은 약 10줄을 목표로 하되 필요한 위험/마이그레이션/리뷰 조치는 보존 |
| 파일/함수 단위 변경 나열 | 의미 단위로 묶어 한 줄씩 |
| 라인 단위 디테일 설명 | diff에 위임. 본문에는 의도만 |
| 이모지 남발 | 이모지 미사용 |
| "파일 여러 개 수정" | 의미 단위 변경 명시 |
| "37 files changed" 통계 | 의미 있는 정보만 (lock 파일 예외) |
| "코드 리팩토링" | "순환 의존성 해결 (lazy import)" |
| 배경 없는 PR | 1-3문장이라도 왜를 적기 |
| 검증/테스트 통과 여부를 본문에 적음 ("pytest 통과", "lint 통과") | 검증 섹션 없음 (CI 가 진실) |
| 별도 `## Breaking Changes` 섹션 | 결과 섹션의 한 bullet 으로 통합 (`기존 X → 변경 Y. 운영 조치 Z`) |
| 이슈와 무관한 내용 | 이슈 맥락 반영 |
| follow-up 후보 줄줄이 나열 | 별도 이슈/코멘트로 분리 |
| AI 세션 맥락 노출 ("§6.7", "SSOT 항목 3번") | 내용을 직접 풀어쓰기 ("기존 stage 체계") |
| 물결 표기 `~text~` (취소선으로 렌더링됨) | "약", "대략" 한국어 또는 하이픈 범위 `1-6건` |
| em dash `—` | 하이픈 `-` 또는 쉼표 `,` |
| middle dot `·` | 쉼표 `,` 또는 슬래시 `/` |
| bullet `•` | 하이픈 `-` |
| 결과/효과 섹션 누락 | "이 PR로 무엇이 달라지는지" 1-3 bullet 필수 |
| 모든 변경에 H3 소제목 | 3개 이상 카테고리일 때만 사용. 기본은 flat 나열 |

## 분량 압축 순서

일반적인 PR 본문이 약 20줄을 넘고 반복이 보이면 다음 순서로 줄입니다.
줄 수를 맞추려고 필수 템플릿, 위험, 마이그레이션 절차, 링크, 검증 한계를
삭제하지 않습니다.

1. 디테일한 변경 나열 → 의미 단위로 묶기 (5개 → 2-3개)
2. 분석 수치 → 가장 인상적인 1-2개만 남기기
3. follow-up/후속 후보 → 제거 (별도 이슈/코멘트로)
4. 배경 문장 → 핵심 한 문장으로 압축 (사실+동기 1문장)
5. 결과 bullet → 사용자 영향 중심 1-3개로 압축. Breaking 영향은 그 안의 한 bullet 으로 흡수
