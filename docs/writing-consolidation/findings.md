# agent 글쓰기 실패의 진단 (2026-09-22~24)

- 병목은 본문 깊이가 아니라 첫 화면의 자기설명 층과, 교정이 다음 pass에서 보존되지 않는 것
- 원인은 규칙 부재가 아니라 여섯 스킬의 무게와 모순, 그리고 취향 층이 스킬 호출에 묶여 있던 구조
- 남은 약점은 원문에 없는 것을 말하는 초안이고, 답은 규칙 추가가 아니라 산문 자리를 줄이는 형태와 원문 대조

근거: 세션 기록, 공유 페이지 네 개의 수기 편집, 익명 비교 시험([harness/](harness/README.md)). 스킬에 반영된 판정은 [adjudication.md](adjudication.md)와 [maintenance.md](maintenance.md).

## 편집이 집중되는 곳

공유 페이지 네 개의 수기 편집을 agent 게시본과 대조했다.

- 편집은 첫 화면(callout, 도입, 요약)에 집중됐다. 본문의 이론, 수식, 그림, 실제 예시, 수치는 한 번도 지워지지 않았다.
- 지운 것은 문서가 자기 자신을 설명하는 층이다. 목적 선언, 범위, 기준일, 읽는 순서, 라벨, 장 예고, 정렬 설명, 상태 요약, 미확인 고지, 다음 계획.
- 사용자가 직접 쓴 텍스트는 네 페이지에서 같은 모양이다. 목표나 주제를 첫 줄에, 명사형으로 끝나는 짧은 bullet을 두 단계로, 개념은 영어 그대로, 입장은 단정형. 이 모양은 도입과 요약에 적용됐고 본문 산문은 그대로 두었다.
- 일부 상태 문장은 요약에 남겼고("비교 근거는 없음"), 일부 수치는 지웠다. 그래서 "상태 문장 금지"는 규칙이 아니라 조건이다: 독자가 그 조건 없이 숫자를 다르게 읽을 때만 남긴다.
- agent는 그 모양을 두 번 되돌렸다. bullet을 산문으로 합치고, 두 단계 개요를 산문으로 다시 썼다. 페이지에 남긴 사용자 메모를 독자용 문장으로 바꾸자 사용자가 지웠다.

## 교정이 쌓이지 않는 이유

수정 세션 세 개를 turn 단위로 봤다.

- agent는 교정 문장만 지우고 같은 기능의 문장을 다른 자리에 다시 쓴다. 재료는 사용자 지시("최신순으로"가 문장으로), reviewer나 subagent의 단서, "설명하라"를 "정의 + 부정형 단서"로 읽은 것이다.
- 교정 한 건마다 문서 전체를 재생성해 문장 유지율이 2~58%였다. 승인된 mechanism과 예시가 함께 사라졌다.
- 스킬은 거의 매 턴 로드됐으므로 규칙이 없어서 생긴 실패는 아니다. 같은 규칙이 4~7곳에 다른 문장으로 있었고, 여섯 스킬을 함께 로드하면 문장 리듬, hedging, 부정 대구, 구두점, 영어 경계, 문장 완결에서 서로 어긋났다.
- 참조 파일 가운데 실제 작성 세션에서 열린 것은 예시 파일 10회, 한국어 tell 130회 이상이었고, 공개 exemplar를 URL로 가리키는 파일 둘은 0회였다. 잘 쓴 글을 모아 모방하려던 시도는 인용 없는 URL 목록이 되어 작동하지 않았다.

## 취향 층은 호출과 무관하게 들어가야 한다

통합 writer를 설치한 다음 날, 스킬을 이름으로 부르지 않은 첫 실제 문서 작업(README 전문 재작성 한 턴)에서 스킬 본문과 취향 파일은 한 번도 컨텍스트에 들어오지 않았다. 전역 지시 파일에 "먼저 읽어라"가 있었지만 스킬은 목록에만 있었다. 참조 파일에 둔 취향은 스킬이 로드될 때만 작동한다. 그래서 취향은 지시 파일에 본문으로 들어가고(import 또는 동기화된 복사본), 스킬은 craft만 가진다.

## 유려한데 나쁜 글

모델이 좋아질수록 문장은 매끄러워지지만 사용자 기준으로는 나빠질 수 있다. 유려함은 접착 문장이다. 소개, 예고, 요약, 전환, 완화, 독자 배려. 사용자가 지운 층과 정확히 겹친다.

비교 시험에서 후보가 설치본보다 나았던 항목은 전부 "하지 마라"가 걸린 곳이고(소개문, 범위 밖 변경, 재생), 끝까지 남은 약점은 "원문에 없는 것을 말하지 마라"였다. 미확정을 확정으로 굳히고, 일반 지식으로 mechanism을 채우고, 후보에 선정 기준을 붙인다. 접착은 금지로 잡히고 발명은 금지로 안 잡힌다.

남은 지렛대는 규칙이 아니라 형태와 검증이다.

1. 산문을 쓸 자리를 줄인다. 첫 화면과 본문의 기본을 개요와 표로 하고, 산문은 mechanism, 원인, trade-off처럼 연결어가 필요한 곳에만. 취향 파일의 기본값이다.
2. 원문 대조를 출력 조건으로 한다. 모든 문장이 원문의 어느 줄에서 왔는지 표시한 판본을 먼저 받고, 표시를 지운 판본을 받는다.
3. diff를 거치지 않은 수정본은 받지 않는다. `protected_diff.py` 결과를 수정마다 함께 낸다.

몇 주 실제 문서에서 교정 횟수를 세어 나쁘면 2와 3을 기본값으로 올린다. 규칙 추가는 [maintenance.md](maintenance.md)의 조건을 통과할 때만 한다.
