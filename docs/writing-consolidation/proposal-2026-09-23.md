# 글쓰기 스킬 통폐합 제안 (2026-09-23)

실행된 결과는 [adjudication.md](adjudication.md)와 [maintenance.md](maintenance.md)에 있다. 이 문서는 실행 전 제안 원문이며, share-internal-doc은 리뷰 뒤 일단 유지했다가 2026-09-24에 흡수했고 use-terminology는 유지했다.

2026년 9월 23일. 네 차례 조사([findings.md](findings.md)에 요약)를 바탕으로, 글쓰기 관련 agent skill 여섯 개를 하나로 합치는 안이다. 목표는 사용자가 스킬만 지정하면 초안부터 사용자 기준에 맞는 글이 나오고, 교정이 다음 pass에서 보존되는 상태다. 사용자는 문서를 쓸 때 관련 스킬을 전부 로드하므로, 스킬 간 모순이 구조적으로 없어야 한다.

## 진단 요약

- 병목은 첫 화면이다. 공유 페이지 네 개의 수기 편집을 agent 게시본과 대조한 결과, 편집은 callout, 도입, 요약에 집중됐고 본문의 이론, 수식, 그림, 실제 예시, 수치는 한 번도 지우지 않았다. 지운 것은 문서가 자기 자신을 설명하는 층(목적 선언, 범위, 기준일, 읽는 순서, 라벨, 장 예고, 정렬 설명, 상태 요약, 미확인 고지, 다음 계획)이다.
- 사용자가 직접 쓴 텍스트는 네 페이지에서 같은 모양이다. 목표나 주제를 첫 줄에, 명사형으로 끝나는 짧은 bullet을 두 단계로, 개념은 영어 그대로, 입장은 단정형. 이 모양은 도입과 요약에만 적용됐고 본문 산문은 그대로 두었다.
- agent는 그 모양을 두 번 되돌렸다(bullet을 산문으로 합침, 두 단계 개요를 산문으로 재작성). 페이지의 사용자 메모를 독자용 문장으로 바꾸자 사용자가 지웠다. 이것이 "고칠수록 산으로 간다"의 실체다.
- 수정 세션의 turn 단위 분석에서, agent는 교정 문장만 지우고 같은 기능의 문장을 다른 자리에 다시 쓴다. 재료는 사용자 지시, reviewer 단서, 부정형 정의다. 교정 한 건마다 문서 전체를 재생성해 문장 유지율이 2~58%였다.
- 스킬은 거의 매 턴 로드됐다. 규칙 부재가 아니라 무게와 모순의 문제다. 참조 파일 중 실제 작성 세션에서 열린 것은 finished-examples 10회, korean-tells 130회 이상이고 source-readings와 example-library는 0회다.

### 통합 SKILL.md의 절 순서

순서가 무게다.

1. 첫 화면과 상시 규칙(20줄 안). 목표나 결론 한 줄 뒤 명사형 두 단계 bullet. 문서 소개문, 상태 문장, 계획 문장 금지. 목표가 자료에 없으면 물어보고 지어내지 않는다. 사용자가 손댄 블록과 페이지 메모는 다음 pass에서 byte 보존, bullet을 산문으로 합치지 않는다. 셀은 짧게. 구두점과 영어 경계. 사용자가 직접 쓴 callout을 형식 예시로.
2. 정보 선택과 구조(현재 SKILL.md 압축).
3. 표와 그림(첫 도식은 문서 주제, 핵심 도식은 접지 않음).
4. 수정 규율(PR #71의 Revision discipline).
5. 한국어와 영어(korean-clarity와 korean-tells에서 근거 있는 것만).
6. 공유와 전달(share-internal-doc에서).
7. 배포 전 검사와 검사 스크립트.

참조는 correction-cases(한국어 교정 전후 12건), exemplar-passages(공개 한국어 기술 글 인용 6건), korean-tells 정리본, finished-examples, information-design 다섯 개. source-readings와 example-library의 URL 115개는 스킬에서 빼고 docs/로 옮긴다.

### 검사 스크립트

배포 전에 초안을 검사한다. 첫 화면에 bullet 앞 산문 문단이 있는지, "이 문서는", "읽는 기준", "기준일", "미확인", "미확보", "논의 중", "아래 표는" 같은 문장이 있는지, 셀 길이가 기준을 넘는 표가 있는지 세어 출력한다. 모델의 주의력에 기대지 않는 유일한 장치이고, 출력이 곧 측정치다.

### 모순 일곱 개의 확정

| 주제 | 확정 |
|---|---|
| 문장 리듬 | 조정하지 않는다. 짧은 문장 연결 규칙 삭제 |
| hedging | 건조한 서술이 기본. 겸양 표현은 사용자가 쓴 것만 보존 |
| 부정 대구 | 실제 대안을 구분할 때만. 스킬 본문도 같은 기준으로 다시 씀 |
| 슬래시 | 표 모서리 라벨만 허용, 제목은 금지 |
| 문장부호 | em-dash와 가운뎃점 본문 금지. 연결어미 뒤 쉼표 규칙 삭제 |
| 영어 경계 | 분야 용어만 영어. 일반 동사와 명사는 한국어. 예문도 교정 |
| 문장 완결 | 본문 산문은 완결. 제목, 셀, 첫 화면 개요 bullet은 fragment 허용 |

### 절차

1. 규칙 목록 추출과 판정표. 여섯 스킬의 모든 명령문을 뽑아 중복을 묶고, 각 묶음에 유지, 삭제, 충돌 해소 판정을 붙여 docs/에 남긴다. 합치면서 규칙이 소리 없이 사라지는 것을 막는 장치다.
2. 통합 SKILL.md와 참조 다섯 개 작성, 검사 스크립트.
3. 이전 스킬 세 저장소에 보관 안내, install lock에서 slop-aware-writing, korean-clarity, share-internal-doc, use-terminology 제거 후 9개 하네스 재설치.
4. 실제 문서 두 편으로 전후 시험. 채점 기준에 과잉 해석 항목 추가, 교정을 세 차례 이상 이어 drift 측정.

### 기각한 대안

- 첫 화면 규칙을 technical-report-writing에 그냥 추가: 100개 넘는 문장 속에서 같은 무게가 되어 묻힌다. 참조 파일은 열리지 않는다.
- 작은 house-style 스킬을 새로 만들고 전역 지시 파일에서 상시 참조: 모순은 남고 우선순위 선언 한 줄에 의존한다. 스킬 수도 늘어난다.
