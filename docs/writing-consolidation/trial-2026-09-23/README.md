# 스킬 전후 시험 (2026-09-23)

같은 한국어 작성 과제를 옛 스킬과 새 스킬로 각각 작성하고, 사용자의 "너무 길어" 수정 요청을 한 차례 적용한 뒤, 채점자가 실패 유형별 문장 수를 셌다. 채점자는 어느 문서가 어느 스킬인지 모르는 상태였다.

| 파일 | 내용 |
|---|---|
| brief.md | 과제와 허용된 사실(가상) |
| revision-request.md | 초안에 대한 사용자 반응 |
| rubric.md | 실패 유형 a~j 채점 기준 |
| mapping.txt | 익명 표지와 arm의 대응 |
| outputs/ | arm별 초안과 수정본. A: Opus 옛 스킬, B: Opus 새 스킬, E: Sonnet 옛 스킬, F: Sonnet 새 스킬 |

옛 스킬은 agent-skills 커밋 b21b6ff(설치본과 동일)이고, 새 스킬은 커밋 6e935c4다. GPT-5.6 Sol arm은 opencodex proxy의 모델 조회 실패로 실행되지 않았다.

## 결과

| arm | 초안 a+b+c+e+f+g | 수정본 합계 | 수정본에서 잃은 핵심 항목 | 지시문이 문장으로 옮겨진 수 |
|---|---|---|---|---|
| Opus 옛 스킬(A) | 15 | 5 | 0 | 0 |
| Opus 새 스킬(B) | 8 | 4 | 0 | 0 |
| Sonnet 옛 스킬(E) | 5 | 0 | 0 | 0 |
| Sonnet 새 스킬(F) | 5 | 1 | 0 | 0 |

Opus 초안에서 자기설명 문장이 9건에서 2건으로, 번역투가 3건에서 1건으로 줄었다. Sonnet은 초안 합계가 같았다. 네 arm 모두 한 차례 수정에서 유지 요청 절을 문장 그대로 보존했고 핵심 항목을 잃지 않았으므로, 실제 세션에서 세 차례 이상 교정 뒤에 나타난 drift는 이 시험 길이로는 재현되지 않았다.

새 스킬 Opus 초안에 남은 실패는 요약 문단에서 제안을 확정된 일처럼 쓴 것("첫 작업은 기존 14건의 분류다")과 셀에 문장이 든 표 하나다. 첫째는 커밋 이후 SKILL.md에 "요약 문단도 제안 지위를 담는다"를 더해 반영했다.

채점 기준의 한계: 관찰과 추론을 구분하는 정당한 단서("근거 문장만으로는 구분할 수 없다")를 b로 감점하고, 브리프에 없는 인과를 단정한 문장(Sonnet 옛 스킬의 "확인하지 않아 놓친 것으로 보인다")은 잡지 못한다. 다음 시험에서는 과잉 해석 항목을 추가하고, 교정을 세 차례 이상 이어서 drift를 측정한다. arm당 표본이 하나라 차이의 크기는 신뢰할 수 없다.
