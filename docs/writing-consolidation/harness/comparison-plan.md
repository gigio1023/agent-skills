# 비교 계획

writer 판본을 설치하기 전에 후보와 설치본의 실제 행동을 같은 과제로 비교한다. 첫 회차(2026-09-23)에서 보완한 한계: arm당 문서 하나, 교정 한 번, 한 모델만 실행, 보존 대상을 요청에서 직접 지정, 정당한 단서를 벌점 처리.

## 비교 대상

| arm | 내용 |
|---|---|
| installed | 지금 설치된 writer와 함께 로드되는 자매 스킬 전부 |
| candidate | 고친 writer 하나만 |
| (선택) 중간 판본 | 특정 커밋의 writer, 같은 자매 스킬 |

자매 스킬 유무가 비교 대상이면 candidate는 스킬 하나만 로드한다. 이 차이가 곧 측정하려는 것이다.

## 과제 1: 긴 연구 문서

원자료: 예시 제작에 쓰지 않은 실제 연구 제안서(20~30KB). 초안 요청: "이 보고서를 동료 연구자가 읽을 Notion 페이지로 다시 써 줘. Markdown으로."

이어지는 교정 세 차례. 실제 세션의 교정을 본떴고, 원자료에 맞게 괄호 안만 바꾼다.

1. "너무 길고 표가 많아. 핵심만 남겨. (유지할 절, 예: 실험 설계의 mechanism과 비교 조건 설명)은 좋으니 그건 유지."
2. "첫 화면에 문서 소개 말고 결론부터. (남길 이유, 예: 첫 후보를 먼저 고르는 이유)는 남겨."
3. "'논의 중' 같은 표현 빼. 이건 내 제안이야. 그리고 (후보 A)와 (후보 B)는 예시 후보지 확정 대상이 아니야."

각 단계 결과를 draft, r1, r2, r3로 저장한다.

## 과제 2: 짧은 PR 본문

원자료: 실제 PR의 diff(파일 두세 개). 요청: "이 diff로 PR 본문을 써 줘. 리뷰 팀은 영어로 읽어." 교정 한 차례: "as-is/to-be 표 넣어."

## 측정

세 층으로 잰다. 한 층만으로 판단하지 않는다.

1. **자동 표시**: `check_draft.py`의 self_description, status_plan, order_narration, negation_definition, long_cell, first_screen_prose 건수. 후보 문장 표시일 뿐 합격 판정이 아니다.
2. **요청 밖 변경**: `protected_diff.py`로 교정 단계마다 지시 범위 밖에서 바뀌거나 사라진 블록 수, 그림과 수식과 표의 삭제 수, 교정 1에서 유지하라고 한 절의 byte 단위 보존.
3. **익명 채점**: [rubric.md](rubric.md)의 교정 추적 항목 a~h.

## 판정

후보를 설치하는 조건. 주 사용 모델에서 (a), (b), (g)가 설치본보다 줄고, (c), (d), (f)가 늘지 않고, 요청 밖 변경 수가 줄어야 한다. 하나라도 어긋나면 그 과제만 반복해 원인을 본 뒤 후보를 고친다.
